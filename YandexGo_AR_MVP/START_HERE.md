# Запуск и свои анимации

## Что изменилось

Ноутбук показывает настоящий интерактивный GLB, а не фиксированную фотографию.
При вращении просмотра координаты 3D-меток проецируются на экран и передаются телефону через сервер.
Камера телефона определяет плоскость экрана по угловым ArUco-меткам и размещает на ней текущую подсказку.
На телефоне остаются кнопки «Назад» и «Далее», один шаг за раз.

Это не распознавание геометрии реального самоката. Угловые квадратные метки нужны, их нельзя убрать.
Телефон можно перемещать перед экраном, пока распознаются минимум три метки.
Обойти изображённый самокат телефоном как настоящий объект нельзя: другой ракурс получают вращением мышью на ноутбуке.

## 1. Запуск из VS Code

1. Распакуйте архив и откройте папку `YandexGo_AR_MVP` в VS Code.
2. Откройте «Терминал → Новый терминал». Убедитесь, что в этой папке лежит `server.py`.
3. Запустите:

```sh
python server.py --port 8000
```

Если Windows не находит python, используйте `py server.py --port 8000`; на macOS/Linux можно `python3 server.py --port 8000`.
Python 3.10+; дополнительных Python-пакетов не требуется.
Оставьте терминал работающим. Для нового режима нужен именно server.py, а не расширение Live Server.

4. На ноутбуке откройте `http://localhost:8000/live.html`.
5. Дождитесь модели и сообщения «3D-точки передаются».
6. Во втором терминале запустите привычный LocalTunnel на порт **8000**. Если используете npx:

```sh
npx localtunnel --port 8000
```

7. На телефоне откройте полученный HTTPS-адрес, добавив `/ar.html?live=1`.
   Пример формы адреса: `https://ВАШ-АДРЕС/ar.html?live=1`.
   Если LocalTunnel покажет свою страницу допуска, сначала пройдите её.
8. Нажмите «Открыть камеру», разрешите доступ и наведите телефон на всю область модели с угловыми метками.
9. После «Самокат найден» нажмите «Начать обучение».

GitHub не нужен. Телефон и ноутбук обращаются к одному запущенному server.py.
Не открывайте несколько live.html одновременно: в стандартной комнате будет действовать последнее обновление.
Для независимых демонстраций задайте одинаковое значение `room` на двух устройствах:
`live.html?room=my-demo` и `ar.html?live=1&room=my-demo`.
Это разделение демонстраций, а не авторизация.

## 2. Проверка перед презентацией

- Модель вращается мышью; колесо меняет масштаб. Оставляйте модель внутри угловых меток.
- Сначала проверьте неподвижный ракурс, затем медленное вращение, затем движение телефона.
- Держите видимыми все четыре квадрата; минимум для работы — три распознанных квадрата.
- Избегайте бликов, сильного наклона экрана и слишком мелких квадратов в камере.
- Данные обновляются примерно до 10 раз в секунду с каждой стороны. Через туннель возможна заметная задержка: резкое вращение может временно рассогласовать модель и эффект. Для ответственного показа вращайте медленно и делайте короткую остановку перед объяснением детали.
- При потере меток эффект скрывается примерно через 0,4 секунды. При остановке передачи с ноутбука — после истечения тайм-аута связи. Длительно устаревшие координаты не должны оставаться на экране.
- Подсказки — плоские GIF/видео/рисунки над изображением модели. Реального перекрытия корпусом и объёмного поворота GIF здесь нет: метка скрытой сзади детали может быть видна поверх корпуса.
- Сервер предназначен для учебной демонстрации, без аккаунтов и постоянного хранения. После показа остановите сервер и туннель Ctrl+C.

## 3. Как вставить GIF друга

Положите файл, например `gas.gif`, сюда:

```text
YandexGo_AR_MVP/assets/animations/gas.gif
```

Откройте `animation-config.js` и замените его содержимое:

```js
export const animations = {
  throttle: {
    src: './assets/animations/gas.gif',
    width: 180,
    height: 180,
    offsetX: 0,
    offsetY: -70
  },
  brake: {
    src: './assets/animations/brake.gif',
    width: 160,
    height: 160,
    offsetX: -40,
    offsetY: -30
  }
};
```

Добавляйте только те записи, для которых у вас есть файлы. Это пример имён, сами `gas.gif` и `brake.gif` в комплект не включены.
Сохраните файл и обновите страницу телефона. Если эффект закэшировался, закройте вкладку и откройте снова.
`width`/`height` — размер в условных пикселях мишени 1120×1000; на телефоне он меняется вместе с масштабом экрана.
`offsetX`: плюс вправо, минус влево. `offsetY`: плюс вниз, минус вверх. Центр анимации привязан к метке.
У GIF желательно прозрачный фон: белый прямоугольник автоматически не удаляется.
GIF отображается нативным элементом img, чтобы воспроизводились кадры анимации.
Если своей записи нет, остаётся встроенная стрелка. При ошибке загрузки возвращается встроенный эффект; проверьте имя и расширение файла, включая регистр.
Встроенные эффекты также остаются до готовности загружаемого файла.

## 4. Видео и другие форматы

Для MP4 или WebM укажите путь тем же способом:

```js
export const animations = {
  throttle: {
    src: './assets/animations/gas.mp4',
    width: 220, height: 160, offsetX: 0, offsetY: -60
  }
};
```

Видео запускается без звука и по кругу; воспроизведение зависит от поддержки кодека браузером.
Обычный MP4 содержит непрозрачный фон. Прозрачность WebM зависит от конкретного устройства — обязательно проверить на телефоне.
GIF, PNG, SVG и WebP подключаются как изображения; анимированные GIF/WebP воспроизводит браузер.
Lottie JSON, проекты After Effects и 3D-анимации FBX/GLB этим загрузчиком не поддерживаются.
Попросите друга экспортировать их в GIF/видео, либо потребуется отдельная доработка под исходный формат.
Для GIF зацикливание задаётся при экспорте. Смена шага создаёт новый элемент; возврат к шагу начинает медиа заново.
Свои медиа работают также в старом режиме камеры и демо без камеры.

## 5. Названия шагов для animation-config.js

| Ключ | Деталь |
| --- | --- |
| `throttle` | Курок газа |
| `brake` | Ручной тормоз |
| `handlebar` | Хват руля |
| `'foot-left'` | Передняя нога |
| `'foot-right'` | Задняя нога |
| `'front-wheel'` | Переднее колесо |
| `'rear-wheel'` | Заднее колесо |
| `'rear-brake'` | Задний тормозной узел |

Ключи с дефисом в JavaScript заключайте в кавычки.
Тексты и порядок урока редактируются в `marker-config.js`.

## 6. Как точно выставить метки

В исходном архиве anchors.json содержит предварительные координаты. Проверьте их до презентации.

1. На ноутбуке в live.html выберите нужную деталь в списке «Настройка меток».
2. Поверните самокат так, чтобы деталь была хорошо видна.
3. Дважды щёлкните по поверхности нужной детали. Точка переместится к месту попадания на 3D-модель.
4. Повторите для остальных меток. Изменения сразу передаются телефону.
5. Нажмите «Скачать anchors.json». Замените этим файлом прежний anchors.json в папке проекта.
6. Обновите live.html. Перед показом выберите «Настройка меток: выключена», чтобы скрыть служебную точку.

До скачивания и замены файла изменения живут только в открытой вкладке и теряются после перезагрузки.
Настройка меняет 3D-точки нового режима. Статический режим по-прежнему использует target-layout.json.
Для встроенного эффекта хвата руля две вспомогательные точки leftGrip/rightGrip заданы отдельно в viewer.js. Если они неточны, измените их там или используйте собственный GIF, привязанный к handlebar.

## 7. Что проверено при подготовке

Автоматически проверены синтаксис JavaScript/Python, распознавание четырёх угловых меток на синтетическом кадре новой мишени, расчёт перспективного преобразования, отказ от привязки при двух оставшихся метках и формула перевода 3D-точек в координаты эффекта при смене камеры.
Запуск полноценного браузера в среде подготовки оказался недоступен. Реальная камера телефона, WebGL-отрисовка, задержка через LocalTunnel и пользовательские GIF/видео здесь не проверены. Нужен пробный запуск на ваших устройствах.
