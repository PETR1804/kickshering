# Обновление устойчивости

Исправлены три причины сбросов: GIF больше не удаляется при временном исчезновении привязки; таймер встроенной анимации не обнуляется при повторном распознавании; единичная ошибка запроса координат не уничтожает последний успешный результат.
Первый захват требует три метки. После захвата можно продолжать по двум разнесённым меткам, если геометрическая проверка пройдена. Камера запрашивает более высокое разрешение; распознавание остаётся ограниченным по размеру для производительности.
Краткий пропуск распознавания удерживает последнюю позицию до 900 мс. Затем эффект скрывается, но GIF не пересоздаётся. При сетевой ошибке данные сохраняются максимум 2500 мс с последнего успешного ответа. Явный ответ сервера об отсутствии модели скрывает эффект сразу.
Настройки в tracking-config.js. Увеличение holdMs уменьшает мигание, но усиливает временное отставание метки при движении телефона. Это удержание последней позиции, не вычисление неизвестного положения. Не стоит делать тайм-аут длиннее нескольких секунд.
Резкое движение, блики и потеря угловых меток по-прежнему могут нарушать привязку. Для демонстрации держите четыре квадрата в кадре и вращайте модель плавно. Сеть LocalTunnel может добавлять задержку.
Запуск прежний: server.py --port 8000, live.html на ноутбуке, HTTPS-адрес/ar.html?live=1 на телефоне. Распакуйте в новую папку, остановите старый сервер и запустите новый из неё. Закройте старую вкладку телефона и откройте новую ссылку. Настоящая камера телефона здесь не проверена.
